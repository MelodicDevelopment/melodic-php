# Scaffold a Middleware

You are adding a new middleware class to a Melodic PHP application. The middleware name is `$ARGUMENTS` (if no argument was provided, ask the user for a name — e.g. "RequestLogging", "ApiKeyAuth", "TenantResolver").

Read `vendor/melodicdev/framework/MELODIC_PHP.md` (the authoritative framework usage reference) before generating code. If it disagrees with `vendor/melodicdev/framework/src/`, the source wins.

## Step 0: Check the Built-ins First

Do not scaffold a duplicate. If one of these covers the request, register it instead (Step 4) and tell the user:

| Need | Built-in | How to get an instance |
|---|---|---|
| CORS | `Melodic\Http\Middleware\CorsMiddleware` | `new CorsMiddleware($app->config('cors') ?? [])` |
| JSON request bodies | `Melodic\Http\Middleware\JsonBodyParserMiddleware` | `new JsonBodyParserMiddleware()` |
| Security headers (nosniff, frame options, referrer policy, HSTS, CSP) | `Melodic\Http\Middleware\SecurityHeadersMiddleware` | `new SecurityHeadersMiddleware([...])` — keys `contentTypeOptions`, `frameOptions`, `referrerPolicy`, `hsts`, `contentSecurityPolicy`, `permissionsPolicy` |
| Rate limiting / throttling | `Melodic\Http\Middleware\RateLimitMiddleware` | `new RateLimitMiddleware($cache, maxAttempts: 60, windowSeconds: 60, paths: [...], methods: [...], keyResolver: fn(Request $r): ?string => ...)` — needs a `Melodic\Cache\CacheInterface` (`CacheServiceProvider`) |
| CSRF protection | `Melodic\Security\CsrfMiddleware` | `$container->get(CsrfMiddleware::class)` (bound by `SecurityServiceProvider`) |
| Bearer-token / cookie authentication | `Melodic\Security\ApiAuthenticationMiddleware`, `WebAuthenticationMiddleware`, `OptionalWebAuthMiddleware` | class name on the route |
| Role / entitlement checks | `Melodic\Security\AuthorizationMiddleware` | `middleware: [AuthorizationMiddleware::class], attributes: ['entitlements' => ['admin']]` |
| Login, OAuth callback, logout endpoints | `Melodic\Security\AuthCallbackMiddleware` | `$container->get(AuthCallbackMiddleware::class)` |

## Step 1: Gather Requirements

Use AskUserQuestion to ask:

1. **What should this middleware do?** Get a brief description of the middleware's purpose.

2. **Should it run before or after the handler?**
    - **Before (Recommended)** — Inspect/modify the request, possibly short-circuit (e.g., auth checks, tenant lookup)
    - **After** — Inspect/modify the response (e.g., add headers, logging)
    - **Both** — Wrap the handler (e.g., timing)

3. **Does it need configuration?** (e.g., API keys, limits, header names)
    - **Yes** — Accept config in constructor
    - **No** — No configuration needed

4. **Where should it run?**
    - **Specific routes / a route group (Recommended)** — only when a route matched; sees route params, route attributes and `userContext`
    - **Every request (global)** — runs before routing, including for 404s

## Step 2: Detect Project Structure

- Check `composer.json` for the PSR-4 namespace (the root namespace is the project's own, not necessarily `App`)
- Look for existing middleware in `src/Middleware/` to match the style
- Find where middleware and routes are registered — `public/index.php` in projects generated by `make:project` (`$app->addMiddleware(...)`, `$app->routes(...)`) — and where container bindings live (`src/Providers/AppServiceProvider.php`)

## Step 3: Create the Middleware

Create `src/Middleware/{Name}Middleware.php`:

```php
<?php

declare(strict_types=1);

namespace {Namespace}\Middleware;

use Melodic\Http\Middleware\MiddlewareInterface;
use Melodic\Http\Middleware\RequestHandlerInterface;
use Melodic\Http\Request;
use Melodic\Http\Response;

class {Name}Middleware implements MiddlewareInterface
{
    public function __construct(
        // Configuration / dependencies if needed, e.g. private readonly string $apiKey,
    ) {}

    public function process(Request $request, RequestHandlerInterface $handler): Response
    {
        // Before: inspect the request, short-circuit by returning a Response,
        // or pass data on: $request = $request->withAttribute('key', $value);

        $response = $handler->handle($request);

        // After: Response is immutable — with*() returns a modified clone.
        return $response->withHeader('X-Custom-Header', 'value');
    }
}
```

`Request` and `Response` are immutable: `$request->withAttribute()` and `$response->withHeader()` / `withoutHeader()` / `withStatus()` / `withBody()` / `withCookie()` return **new** objects — reassign or return the result (there are no `setHeader()`-style setters). Useful request methods: `method()`, `path()`, `query()`, `body()`, `header()`, `bearerToken()`, `cookie()`, `ip()`, `isSecure()`, `wantsJson()`, `getAttribute()`. Read a response with `getStatusCode()`, `getHeader()`, `getBody()`.

### Pattern: Before-only middleware

```php
// use Melodic\Http\JsonResponse;
public function process(Request $request, RequestHandlerInterface $handler): Response
{
    if (!hash_equals($this->apiKey, (string) $request->header('X-Api-Key'))) {
        return new JsonResponse(['error' => 'Forbidden'], 403);
    }

    return $handler->handle($request);
}
```

Instead of building the response you can throw `Melodic\Http\Exception\HttpException::forbidden('...')` (or `new HttpException($status, $message)`); the framework's error handler renders it as JSON for `/api/...` paths and JSON requests, HTML otherwise.

### Pattern: After-only middleware

```php
public function process(Request $request, RequestHandlerInterface $handler): Response
{
    return $handler->handle($request)->withHeader('X-Request-Id', bin2hex(random_bytes(8)));
}
```

### Pattern: Wrapping middleware

```php
public function process(Request $request, RequestHandlerInterface $handler): Response
{
    $start = microtime(true);
    $response = $handler->handle($request);

    return $response->withHeader('X-Response-Time', sprintf('%.1fms', (microtime(true) - $start) * 1000));
}
```

Exceptions thrown further in (404/405, `HttpException`s, CSRF failures, errors in controllers or services) are converted to responses by the framework's outermost error handler, so the code after `$handler->handle()` does **not** run for them. Use `try { ... } finally { ... }` for work that must always happen (logging, cleanup) and let the exception propagate.

### Pattern: Header-only middleware (also covers error responses)

A **global** middleware whose only job is adding response headers should also implement `Melodic\Http\Middleware\ResponseDecoratorInterface`; the framework then calls `decorate()` on the error responses it builds, so 404s, 403s and 500s carry the headers too:

```php
class {Name}Middleware implements MiddlewareInterface, ResponseDecoratorInterface
{
    public function process(Request $request, RequestHandlerInterface $handler): Response
    {
        return $this->decorate($request, $handler->handle($request));
    }

    public function decorate(Request $request, Response $response): Response
    {
        return $response->withHeader('X-App-Version', '1.0');
    }
}
```

## Step 4: Show Registration

### Route-specific (class-name string)

Route and group middleware are given as **class-name strings** and resolved with `$container->get()` on each matching request:

```php
$router->group('/api', function (Router $router) {
    // routes...
}, middleware: [{Name}Middleware::class]);

$router->get('/reports', ReportController::class, 'index', middleware: [{Name}Middleware::class]);
```

- No constructor, or only class-typed dependencies the container can resolve → nothing else to do (auto-wired).
- Scalar/array config in the constructor → it **must** be bound, or resolution throws a `ContainerException`. In `AppServiceProvider::register()`:

```php
$container->singleton({Name}Middleware::class, fn(Container $c) => new {Name}Middleware(
    (string) $c->get(Configuration::class)->get('{name}.apiKey'),
));
```

- Different settings per route: declare them as route attributes and read them in `process()` (this is how `AuthorizationMiddleware` gets its entitlements):

```php
$router->get('/admin', AdminController::class, 'index',
    middleware: [{Name}Middleware::class], attributes: ['{name}' => ['level' => 'strict']]);

$options = $request->getAttribute('route.attributes')['{name}'] ?? [];
```

- Order: group middleware (outer groups first), then the route's own, in array order. Put it after `ApiAuthenticationMiddleware` / `WebAuthenticationMiddleware` if it reads `$request->getAttribute('userContext')`. The matched `Route` (`route` attribute) and route params (attributes by name) are available.

### Global (instance)

```php
// public/index.php — after providers are registered, before $app->run()
$app->addMiddleware(new {Name}Middleware(/* config, e.g. $app->config('{name}') ?? [] */));
// or, when it has dependencies:
$app->addMiddleware($app->getContainer()->get({Name}Middleware::class));
```

Global middleware take an **instance**, run for every request in the order added (after the built-in error handler, before routing), and therefore see no route attributes and no `userContext`. Keep `JsonBodyParserMiddleware` ahead of anything that reads `$request->body()`.

Print:

## Important

- Follow all conventions from CLAUDE.md
- Use `declare(strict_types=1)`
- Use constructor promotion and readonly for config parameters
- Match the style of existing middleware in the project
- The middleware MUST implement `Melodic\Http\Middleware\MiddlewareInterface`
- The `process()` method signature is: `process(Request $request, RequestHandlerInterface $handler): Response`
- Always return the Response produced by `with*()` calls — the original object is unchanged
- Run `php -l` on the new file
