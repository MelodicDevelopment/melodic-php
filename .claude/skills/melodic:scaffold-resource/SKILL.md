# Scaffold a CQRS Resource

You are adding a new domain entity to a Melodic PHP application. The entity name is `$ARGUMENTS` (if no argument was provided, ask the user for the entity name — e.g. "Post", "Product", "Order").

Read `vendor/melodicdev/framework/MELODIC_PHP.md` (the authoritative framework usage reference) before generating code. If it disagrees with `vendor/melodicdev/framework/src/`, the source wins.

## Step 1: Gather Requirements

Use AskUserQuestion to ask:

1. **Entity fields**: What fields does this entity have? Suggest common defaults based on the entity name and let the user customize. Always include `id` (auto-increment int) and `createdAt` (datetime string). Provide 2-3 suggested fields based on the entity name (e.g. for "Post": title, body; for "Product": name, price, description).

2. **Controller type**: What kind of controller?
    - **API only (Recommended)** — JSON API controller with full CRUD
    - **Web + API** — Both MVC views and JSON API endpoints
    - **Web only** — MVC views with forms

3. **Auth required**: Should the routes require authentication?
    - **Yes (Recommended)** — Wrap in auth middleware
    - **No** — Public routes

## Step 2: Detect Project Structure

Before creating files, read the project to understand:

- `composer.json` — the PSR-4 root namespace (`{Namespace}` below; it is the project's own name, e.g. `MyApp`, not necessarily `App`)
- `src/` — the standard layout is `Controllers/`, `Services/`, `DTO/`, `Data/{Entity}/Queries|Commands/`, `Middleware/`, `Providers/`. If the project uses a different layout, follow the project.
- Where routes are registered — `$app->routes(...)` in `public/index.php` for projects generated by `make:project`
- `src/Providers/AppServiceProvider.php` — confirm `DbContextInterface` is bound (services cannot be resolved without it; `make:project` does not bind it — see `/melodic:scaffold-app` for the binding)
- An existing Model + Query, to learn the **column naming** convention and database driver
- Whether the project uses migrations (a `migrations/` directory, migrate commands in `bin/console`)
- If auth is required: `SecurityServiceProvider` must be registered in `public/index.php` and `auth` configured; for cookie-authenticated pages `CsrfMiddleware` should be registered globally

Placeholders: `{Entity}` = singular PascalCase (`BlogPost`), `{Plural}` = plural PascalCase (`BlogPosts`), `{entity}` = camelCase (`blogPost`), `{table}` = plural snake_case (`blog_posts`), `{path}` = plural kebab-case (`blog-posts`). `{id}` / `{id:\d+}` in route patterns and `{$var}` inside PHP strings are literal. Paths and class names match `vendor/bin/melodic make:entity {Entity}`; write the files yourself — the CLI's Create/Update commands and controller are TODO stubs.

**Column ↔ property rule.** `DbContext` hydrates by assigning each result column to the public property with the **identical, case-sensitive name** — no snake_case/camelCase conversion; a property with no matching column stays uninitialized. JSON output uses `lcfirst(property)`; request input matches a key as-is or `ucfirst`'d. So:

- Follow the existing tables' convention. For a new schema, name columns exactly like the properties (`title`, `createdAt`).
- snake_case table → alias every such column in SELECTs (`created_at AS createdAt`) and use the real column names in INSERT/UPDATE.
- PostgreSQL folds unquoted identifiers to lower case: quote mixed-case columns and aliases (`"createdAt"`) in DDL and SQL.

## Step 3: Create the Files

### 3a. Model and request DTOs — `src/DTO/`

`{Entity}Model.php` — one public typed property per selected column:

```php
<?php

declare(strict_types=1);

namespace {Namespace}\DTO;

use Melodic\Data\Model;

class {Entity}Model extends Model
{
    public int $id;
    public string $title;
    public ?string $body;      // nullable column → nullable type
    public bool $published;
    public string $createdAt;
}
```

Use `int`, `string`, `float`, `bool` (nullable where the column is). Backed enums and `\DateTimeImmutable` are also hydrated and serialized (dates as ISO-8601 in JSON); keep plain `string` timestamps unless the user wants date objects.

`Create{Entity}Request.php` — the request body for `store`. Only client-writable fields (no `id`, no `createdAt`). Every property must be `#[Required]`, nullable, or have a default — a missing non-nullable property stays uninitialized.

```php
<?php

declare(strict_types=1);

namespace {Namespace}\DTO;

use Melodic\Data\Model;
use Melodic\Validation\Rules\MaxLength;
use Melodic\Validation\Rules\Required;

class Create{Entity}Request extends Model
{
    #[Required]
    #[MaxLength(200)]
    public string $title;

    public ?string $body;

    public bool $published = false;
}
```

`Update{Entity}Request.php` — same fields for a partial update (PUT and PATCH both map to `update`): **no** `#[Required]`, no defaults. Give NOT NULL columns a non-nullable type (an explicit `null` is then rejected with 400) and nullable columns a nullable type (explicit `null` clears the column).

Rules live in `Melodic\Validation\Rules`: `Required`, `Email`, `Url`, `Uuid`, `Date('Y-m-d')`, `MinLength(n)`, `MaxLength(n)`, `Min(n)`, `Max(n)`, `Pattern('/regex/')`, `In([...])`. All except `Required` pass on a missing/null value. Mark server-controlled properties on a reused model with `#[Melodic\Data\Guarded]`.

### 3b. Queries — `src/Data/{Entity}/Queries/`

**GetAll{Plural}Query.php**

```php
<?php

declare(strict_types=1);

namespace {Namespace}\Data\{Entity}\Queries;

use Melodic\Data\DbContextInterface;
use Melodic\Data\QueryInterface;
use {Namespace}\DTO\{Entity}Model;

class GetAll{Plural}Query implements QueryInterface
{
    private readonly string $sql;

    public function __construct()
    {
        $this->sql = "SELECT * FROM {table} ORDER BY id DESC";
    }

    public function getSql(): string
    {
        return $this->sql;
    }

    /** @return array<{Entity}Model> */
    public function execute(DbContextInterface $context): array
    {
        return $context->query({Entity}Model::class, $this->sql);
    }
}
```

**Get{Entity}ByIdQuery.php** — same shape; constructor `(private readonly int $id)`, SQL `SELECT * FROM {table} WHERE id = :id`, and

```php
public function execute(DbContextInterface $context): ?{Entity}Model
{
    return $context->queryFirst({Entity}Model::class, $this->sql, ['id' => $this->id]);
}
```

**Pagination (only if the user wants it).** Give the query `int $page, int $perPage` and return `Melodic\Data\Paginator::paginate($context, {Entity}Model::class, $this->sql, [], $this->page, $this->perPage)` — a `PaginatedResult` that serializes to `{items, total, page, perPage, pageCount}`. Bind the paging parameters from the query string with a Model DTO (`public int $page = 1; public int $perPage = 25;`) and `public function index(#[FromQuery] {Entity}Filter $filter)` (`Melodic\Routing\FromQuery`).

### 3c. Commands — `src/Data/{Entity}/Commands/`

All implement `Melodic\Data\CommandInterface` (`getSql(): string`, `execute(DbContextInterface $context): int` returning affected rows). Always use bound parameters.

**Create{Entity}Command.php** — `toPascalArray()` returns the request's initialized properties keyed by property name, so the placeholders must be exactly the request DTO's properties (PDO rejects unused or missing params):

```php
class Create{Entity}Command implements CommandInterface
{
    private readonly string $sql;

    public function __construct(
        private readonly Create{Entity}Request $request,
    ) {
        $this->sql = "INSERT INTO {table} (title, body, published, createdAt)
            VALUES (:title, :body, :published, :createdAt)";
    }

    public function getSql(): string
    {
        return $this->sql;
    }

    public function execute(DbContextInterface $context): int
    {
        return $context->command($this->sql, [
            ...$this->request->toPascalArray(),
            'createdAt' => date('Y-m-d H:i:s'),
        ]);
    }
}
```

**Update{Entity}Command.php** — partial update from `Update{Entity}Request::toUpdateArray()`, which contains only the fields the client sent, keyed by declared property name (never by raw client keys, so they are safe as column names):

```php
class Update{Entity}Command implements CommandInterface
{
    private readonly string $sql;

    /** @param array<string, mixed> $fields column => value, from Update{Entity}Request::toUpdateArray() */
    public function __construct(
        private readonly int $id,
        private readonly array $fields,
    ) {
        $set = implode(', ', array_map(fn(string $column) => "{$column} = :{$column}", array_keys($fields)));
        $this->sql = "UPDATE {table} SET {$set} WHERE id = :id";
    }

    public function getSql(): string
    {
        return $this->sql;
    }

    public function execute(DbContextInterface $context): int
    {
        return $context->command($this->sql, [...$this->fields, 'id' => $this->id]);
    }
}
```

(If columns are named differently from the properties, map property → column explicitly in both commands.)

**Delete{Entity}Command.php** — constructor `(private readonly int $id)`, SQL `DELETE FROM {table} WHERE id = :id`, `execute()` returns `$context->command($this->sql, ['id' => $this->id])`.

### 3d. Service — `src/Services/{Entity}Service.php`

```php
<?php

declare(strict_types=1);

namespace {Namespace}\Services;

use Melodic\Service\Service;
// + use the DTOs, Queries and Commands above

class {Entity}Service extends Service
{
    /** @return array<{Entity}Model> */
    public function getAll(): array
    {
        return (new GetAll{Plural}Query())->execute($this->context);
    }

    public function getById(int $id): ?{Entity}Model
    {
        return (new Get{Entity}ByIdQuery($id))->execute($this->context);
    }

    public function create(Create{Entity}Request $request): int
    {
        (new Create{Entity}Command($request))->execute($this->context);

        return $this->context->lastInsertId();
    }

    public function update(int $id, Update{Entity}Request $request): int
    {
        $fields = $request->toUpdateArray();

        return $fields === [] ? 0 : (new Update{Entity}Command($id, $fields))->execute($this->context);
    }

    public function delete(int $id): int
    {
        return (new Delete{Entity}Command($id))->execute($this->context);
    }
}
```

Do not add a constructor: `Service` already takes `DbContextInterface` and the container auto-wires the class. Create a `{Entity}ServiceInterface` (and bind it in Step 4) **only** if the project's existing services use interfaces.

### 3e. API Controller — `src/Controllers/{Entity}Controller.php` (if API)

```php
<?php

declare(strict_types=1);

namespace {Namespace}\Controllers;

use Melodic\Controller\ApiController;
use Melodic\Http\JsonResponse;
use Melodic\Http\Response;
use {Namespace}\DTO\Create{Entity}Request;
use {Namespace}\DTO\Update{Entity}Request;
use {Namespace}\Services\{Entity}Service;

class {Entity}Controller extends ApiController
{
    public function __construct(
        private readonly {Entity}Service ${entity}Service,
    ) {}

    public function index(): JsonResponse
    {
        return $this->json($this->{entity}Service->getAll());
    }

    public function show(int $id): JsonResponse
    {
        ${entity} = $this->{entity}Service->getById($id);

        return ${entity} !== null ? $this->json(${entity}) : $this->notFound();
    }

    public function store(Create{Entity}Request $request): JsonResponse
    {
        $id = $this->{entity}Service->create($request);

        return $this->created($this->{entity}Service->getById($id), "/api/{path}/{$id}");
    }

    public function update(int $id, Update{Entity}Request $request): JsonResponse
    {
        if ($this->{entity}Service->getById($id) === null) {
            return $this->notFound();
        }

        $this->{entity}Service->update($id, $request);

        return $this->json($this->{entity}Service->getById($id));
    }

    public function destroy(int $id): Response
    {
        $this->{entity}Service->delete($id);

        return $this->noContent();
    }
}
```

How this works: `int $id` is coerced from the `{id}` route param (non-numeric → 400). A `Model`-typed parameter is hydrated from the request body and validated before the action runs; failures return 400 with `{"field": ["message"]}`. Models are `JsonSerializable`, so pass them straight to `json()`. `$this->getUserContext()` gives the authenticated user when an auth middleware is on the route.

### 3f. MVC Controller — `src/Controllers/{Entity}PageController.php` (if Web)

(`{Entity}Controller` is the API controller; with Web only you may name the MVC controller `{Entity}Controller` instead.)

- Extend the project's base MVC controller if it has one (e.g. `AppController` from `/melodic:scaffold-app`), otherwise `Melodic\Controller\MvcController` and call `$this->setLayout('layouts/main')` in each action. The constructor must accept `ViewEngine $viewEngine` and call `parent::__construct($viewEngine)`; add `private readonly {Entity}Service ${entity}Service` and `private readonly Melodic\Validation\Validator $validator`.
- `index(): Response` → `$this->view('{path}/index', ['{entity}s' => $this->{entity}Service->getAll()])`
- `show(int $id): Response` → `$this->{entity}Service->getById($id) ?? throw new NotFoundException()` (`Melodic\Http\Exception\NotFoundException`, renders the HTML 404 page)
- `create(): Response` → the form view with `['errors' => [], 'old' => []]`
- `store(): Response` — bind by hand, because a `Model`-typed action parameter would answer invalid input with a JSON 400 instead of re-rendering the form:

```php
public function store(): Response
{
    $input = $this->request->body();

    try {
        $request = Create{Entity}Request::fromArray($input);
        $errors = $this->validator->validate($request)->errors;
    } catch (ModelBindingException $e) {          // Melodic\Data\ModelBindingException
        $errors = [$e->field => [$e->getMessage()]];
    }

    if ($errors !== []) {
        return $this->view('{path}/create', ['errors' => $errors, 'old' => $input])->withStatus(422);
    }

    $id = $this->{entity}Service->create($request);

    return $this->redirect("/{path}/{$id}");
}
```

### 3g. Views (if Web) — `views/{path}/`

- `index.phtml` — table/list of all entities with links to `show` and `create`
- `show.phtml` — single entity detail
- `create.phtml` — form posting to `/{path}`; repopulate from `$old`, print `$errors['field']` messages

Templates are plain PHP; `$this` is the `ViewEngine`, the data array's keys are variables, plus `$viewBag`. Output is **not** auto-escaped — wrap every dynamic value in `$this->e()`:

```php
<?php foreach (${entity}s as ${entity}): ?>
    <li><a href="/{path}/<?= $this->e(${entity}->id) ?>"><?= $this->e(${entity}->title) ?></a></li>
<?php endforeach; ?>

<form method="POST" action="/{path}">
    <?= $csrfField ?? '' ?>
    <input type="text" name="title" value="<?= $this->e($old['title'] ?? '') ?>">
    <?php foreach ($errors['title'] ?? [] as $message): ?><p class="error"><?= $this->e($message) ?></p><?php endforeach; ?>
    <button type="submit">Create</button>
</form>
```

**CSRF.** `$csrfField` (a ready-made hidden `csrf_token` input, the one value printed unescaped) exists when `Melodic\Security\CsrfMiddleware` is registered globally; it then rejects any POST without the token with 403. If the pages are cookie-authenticated and `public/index.php` does not register it yet, add after `JsonBodyParserMiddleware`: `$app->addMiddleware($app->getContainer()->get(CsrfMiddleware::class));` (bound by `SecurityServiceProvider`).

## Step 4: Update Existing Files

### Routes

Add to the `$app->routes(function ($router) { ... })` callback (in `public/index.php` unless the project keeps routes elsewhere). Middleware are class-name strings resolved from the container:

```php
// API — inside the existing /api group if there is one
$router->group('/api', function (Router $router) {
    $router->apiResource('/{path}', {Entity}Controller::class);   // index, show, store, update (PUT + PATCH), destroy
}, middleware: [ApiAuthenticationMiddleware::class]);              // omit when public

// Web — literal paths before parameterised ones (first match wins)
$router->group('/{path}', function (Router $router) {
    $router->get('', {Entity}PageController::class, 'index');
    $router->get('/create', {Entity}PageController::class, 'create');
    $router->post('', {Entity}PageController::class, 'store');
    $router->get('/{id:\d+}', {Entity}PageController::class, 'show');   // non-numeric id → 404 page
}, middleware: [WebAuthenticationMiddleware::class]);              // omit when public
```

Add the `use` statements (`Melodic\Routing\Router`, the controllers, `Melodic\Security\ApiAuthenticationMiddleware` / `WebAuthenticationMiddleware`). To restrict by role, add `AuthorizationMiddleware::class` after the authentication middleware and `attributes: ['entitlements' => ['admin']]`. Keep JSON endpoints under `/api` — the error handler only returns JSON errors for `/api/...` paths or JSON requests. JSON request bodies need `JsonBodyParserMiddleware` registered globally (it is, in generated projects).

### Service binding

None needed — controllers and services are auto-wired. Only when you created a service interface:

```php
// src/Providers/AppServiceProvider.php → register()
$container->bind({Entity}ServiceInterface::class, {Entity}Service::class);
```

## Step 5: Database Migration

Column names must follow the rule from Step 2:

```sql
CREATE TABLE {table} (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    -- ... fields based on user input
    createdAt TEXT NOT NULL
);

-- @down
DROP TABLE {table};
```

- Project uses migrations → write this to `migrations/{YYYYMMDDHHMMSS}_create_{table}.sql` (current timestamp; statements end with `;` at a line end; everything after `-- @down` is the rollback) and tell the user to run `php bin/console migrate`.
- Otherwise → show the `CREATE TABLE` statement for the user to run.

Adjust syntax for the database driver (`INT AUTO_INCREMENT PRIMARY KEY` / `DATETIME` for MySQL; `SERIAL PRIMARY KEY` / `TIMESTAMP` and quoted `"createdAt"` for PostgreSQL). Booleans: `INTEGER` / `TINYINT(1)` / `BOOLEAN`.

## Important

- Follow all conventions from CLAUDE.md
- Match the existing code style in the project (check an existing Query, Command, Service, or Controller for reference)
- Use `declare(strict_types=1)` in every file
- Table name is plural snake_case (e.g. entity "BlogPost" → table "blog_posts")
- URL path is plural lowercase with hyphens for multi-word (e.g. "BlogPost" → "/blog-posts")
- The entity class name is always singular PascalCase
- No SQL in services or controllers; no user input interpolated into SQL
- Run `php -l` on every file you created
