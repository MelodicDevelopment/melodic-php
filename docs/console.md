# Console

Melodic includes a lightweight CLI console for running commands from the terminal. It provides a `Console` runner, a `Command` base class with output helpers, and several built-in commands.

There are two entry points:

- **`vendor/bin/melodic`** — the framework's own binary. It registers the scaffolding commands only: `make:project`, `make:entity`, `make:config`, and `claude:install`.
- **Your application's `bin/console`** — a script you own. `route:list`, `cache:clear`, and the database migration commands ship with the framework but need your application's router, cache, or database, so you register them (and your own commands) here. The `bin/console` generated by `make:project` creates a `Console` and registers no commands.

## Quick Start

Create a console entry point (e.g. `bin/console`):

```php
#!/usr/bin/env php
<?php

declare(strict_types=1);

require_once __DIR__ . '/../vendor/autoload.php';

use Melodic\Cache\CacheInterface;
use Melodic\Console\Console;
use Melodic\Console\CacheClearCommand;
use Melodic\Console\RouteListCommand;

// $app is your configured Melodic\Core\Application: config loaded,
// service providers registered, routes defined (everything except run()).

$console = new Console();
$console->setName('My App');
$console->setVersion('1.0.0');

// Register built-in commands
$console->register(new RouteListCommand($app->getRouter()));
$console->register(new CacheClearCommand($app->getContainer()->get(CacheInterface::class)));

// Register custom commands
$console->register(new GreetCommand());

exit($console->run($argv));
```

`route:list` can only show routes that have been registered on the `Router` it is given, and `cache:clear` clears the `CacheInterface` instance it is given. The scaffolded `public/index.php` builds the application inline, so to share it with the console, move the bootstrap (everything up to but not including `$app->run()`) into a file that both `public/index.php` and `bin/console` require.

`setName()` and `setVersion()` are optional; they default to `Melodic Console` and the framework version (`Melodic\Framework::VERSION`).

```bash
php bin/console                  # shows help with all available commands
php bin/console help             # same as above
php bin/console route:list       # list all registered routes
php bin/console cache:clear      # clear the application cache
```

`Console::run()` returns the command's exit code. Running with no command or with `help` prints the command list and returns `0`; an unknown command prints `Unknown command: …` followed by the list and returns `1`. Registering a second command with the same name replaces the first.

## Writing Custom Commands

Extend the `Command` base class:

```php
use Melodic\Console\Command;

class GreetCommand extends Command
{
    public function __construct()
    {
        parent::__construct('greet', 'Greet a user by name');
    }

    public function execute(array $args): int
    {
        $name = $args[0] ?? 'World';
        $this->writeln("Hello, {$name}!");
        return 0;
    }
}
```

```bash
php bin/console greet Alice
# Hello, Alice!
```

`$args` is everything after the command name, exactly as typed (`array_slice($argv, 2)`). The console does no option parsing — flags such as `--force` or `--type=api` arrive as plain strings and each command inspects them itself.

### Return Codes

The `execute()` method returns an integer exit code:
- `0` — success
- Non-zero — failure

### Output Helpers

The `Command` base class provides these `protected` helpers:

| Method | Description |
|---|---|
| `writeln(string $text)` | Write to stdout with a newline |
| `write(string $text)` | Write to stdout without a newline |
| `error(string $text)` | Write to stderr with a newline |
| `table(array $headers, array $rows)` | Render a formatted ASCII table (cells must be strings) |

Column widths are measured in characters when the `mbstring` extension is loaded and in bytes otherwise (the extension is optional).

### Table Output

```php
$this->table(
    ['Method', 'Path', 'Controller'],
    [
        ['GET', '/users', 'UserController'],
        ['POST', '/users', 'UserController'],
    ],
);
```

Output:

```
+--------+--------+----------------+
| Method | Path   | Controller     |
+--------+--------+----------------+
| GET    | /users | UserController |
| POST   | /users | UserController |
+--------+--------+----------------+
```

## Implementing CommandInterface

For full control without extending `Command`, implement `CommandInterface` directly:

```php
use Melodic\Console\CommandInterface;

class CustomCommand implements CommandInterface
{
    public function getName(): string
    {
        return 'custom:run';
    }

    public function getDescription(): string
    {
        return 'A fully custom command';
    }

    public function execute(array $args): int
    {
        // your logic
        return 0;
    }
}
```

## Built-in Commands

| Command | Class | Registered in |
|---|---|---|
| `make:project` | `Melodic\Console\Make\MakeProjectCommand` | `vendor/bin/melodic` |
| `make:entity` | `Melodic\Console\Make\MakeEntityCommand` | `vendor/bin/melodic` |
| `make:config` | `Melodic\Console\Make\MakeConfigCommand` | `vendor/bin/melodic` |
| `claude:install` | `Melodic\Console\ClaudeInstallCommand` | `vendor/bin/melodic` |
| `route:list` | `Melodic\Console\RouteListCommand` | your `bin/console` (register it yourself) |
| `cache:clear` | `Melodic\Console\CacheClearCommand` | your `bin/console` (register it yourself) |
| `migrate`, `migrate:rollback`, `migrate:status`, `make:migration` (since 4.1) | `Melodic\Console\MigrateCommand`, `MigrateRollbackCommand`, `MigrateStatusCommand`, `MakeMigrationCommand` | your `bin/console` (register them yourself) |

The scaffolding commands work relative to the current working directory, and they validate their name argument before writing anything (4.0): a name containing path separators, dots, quotes, or other non-identifier characters is rejected with exit code `1`.

### `route:list`

Displays all registered routes in a table with Method, Path, Controller, and Action columns, or `No routes registered.` when the router is empty. Requires a `Router` instance.

### `cache:clear`

Calls `CacheInterface::clear()` to flush all cached data. Requires a `CacheInterface` instance. Exits with `1` if the cache reports a failure. See [Cache](cache.md).

### `make:project`

```bash
vendor/bin/melodic make:project my-app               # full: MVC + API (default)
vendor/bin/melodic make:project my-api --type=api    # API only, no views
vendor/bin/melodic make:project my-site --type=mvc   # MVC only
```

Creates a new project in `./<name>/` and fails if that directory already exists. The name may contain letters, digits, dashes, and underscores and must start with a letter; it becomes the Composer package name (`app/<name>`) and, in PascalCase, the root namespace (`my-app` → `MyApp\`). An unrecognised `--type` value falls back to `full`.

Generated files:

- `composer.json` — requires `melodicdev/framework` at `^{major}.{minor}` of the framework version that ran the command (e.g. `^4.1`)
- `config/config.json`, `config/config.qa.json`, `config/config.pd.json` — see [Configuration](configuration.md)
- `public/index.php`, `public/.htaccess`
- `bin/console` — executable, with no commands registered (it contains a commented-out example that registers the migration commands)
- `src/Providers/AppServiceProvider.php`
- `.gitignore` — ignores `vendor/`, `storage/cache/*`, `storage/logs/*`, `config/config.dev.json`, `.env`
- empty `src/Controllers`, `src/Services`, `src/DTO`, `src/Data`, `src/Middleware`, `storage/cache`, `storage/logs`, and `tests` directories (each with a `.gitkeep`)
- `full` and `mvc` only: `src/Controllers/HomeController.php`, `views/layouts/main.phtml`, `views/home/index.phtml`

The generated MVC home page works out of the box: `Application` binds a default `ViewEngine` for `{basePath}/views` (since 4.1 — earlier versions required you to register a `ViewEngine` yourself).

### `make:entity`

```bash
vendor/bin/melodic make:entity Church
vendor/bin/melodic make:entity BlogPost
vendor/bin/melodic make:entity blog-post     # → BlogPost
```

Generates a CQRS skeleton for one entity. Run it from the project root: it reads `composer.json` in the current directory and uses the **first** PSR-4 autoload entry for the namespace and source directory. It takes the entity name and no other options.

For `make:entity Church` in a project whose PSR-4 root is `App\` → `src/`, eight files are written:

| File | Contents |
|---|---|
| `src/DTO/ChurchModel.php` | `Model` subclass with a single `public int $id` |
| `src/Data/Church/Queries/GetAllChurchesQuery.php` | `SELECT * FROM churches` |
| `src/Data/Church/Queries/GetChurchByIdQuery.php` | `SELECT * FROM churches WHERE id = :id` |
| `src/Data/Church/Commands/CreateChurchCommand.php` | `INSERT` with placeholder columns — **TODO, not runnable as generated** |
| `src/Data/Church/Commands/UpdateChurchCommand.php` | `UPDATE … WHERE id = :id` with placeholder columns — **TODO, not runnable as generated** |
| `src/Data/Church/Commands/DeleteChurchCommand.php` | `DELETE FROM churches WHERE id = :id` |
| `src/Services/ChurchService.php` | `getAll()`, `getById()`, `create()`, `update()`, `delete()` |
| `src/Controllers/ChurchController.php` | `ApiController` with `index`, `show`, `store`, `update`, `destroy` |

Things to know:

- **Existing files are never overwritten.** Each one is reported as `skip`, and the command still exits `0`.
- **Naming.** The name is converted to PascalCase: it is split on dashes, underscores, and spaces, and each word is capitalised. A word that is already mixed-case keeps its inner capitals, while an all-lower or all-upper word is normalised — `BlogPost`, `blog-post`, `blog_post`, and `"blog post"` all give `BlogPost`, and `USER` gives `User`.
- **Table name.** The entity name is pluralised with simple English rules and snake-cased: `Church` → `churches`, `Category` → `categories`, `blog-post` → `blog_posts`. Adjust the SQL if your table is named differently.
- **Finish the write path.** The create and update commands contain `/* column */` placeholders, and the generated service and controller do not pass any request data to them. Add your columns, constructor parameters, and model properties before using `store`/`update`.
- **Nothing is registered for you.** Add the route yourself — the controller's action names match `apiResource()`:

  ```php
  $router->apiResource('/api/churches', ChurchController::class);
  ```

  The service extends `Melodic\Service\Service`, so a `DbContextInterface` binding must exist in the container.
- `.gitkeep` files in `DTO/`, `Data/`, `Services/`, and `Controllers/` are removed once those directories have content.

### `make:config`

```bash
vendor/bin/melodic make:config staging
```

Creates `config/config.staging.json` (and the `config/` directory if needed) in the current directory, containing `app.debug: false` and an empty `database.dsn` placeholder. The environment name is lower-cased and may contain letters, digits, dashes, and underscores. The command refuses to overwrite an existing file. See [Configuration](configuration.md).

### Database migrations

Four commands (since 4.1) drive `Melodic\Data\Migration\Migrator`, which applies plain `.sql` files in file-name order and records them in a `melodic_migrations` table. Register them in your `bin/console` with a `Migrator` built from your `DbContext` and migrations directory:

```php
use Melodic\Console\MakeMigrationCommand;
use Melodic\Console\MigrateCommand;
use Melodic\Console\MigrateRollbackCommand;
use Melodic\Console\MigrateStatusCommand;
use Melodic\Data\Migration\Migrator;

$migrator = new Migrator($dbContext, __DIR__ . '/../migrations');

$console->register(new MigrateCommand($migrator));
$console->register(new MigrateRollbackCommand($migrator));
$console->register(new MigrateStatusCommand($migrator));
$console->register(new MakeMigrationCommand(__DIR__ . '/../migrations'));
```

| Command | Description |
|---|---|
| `make:migration <name>` | Create `{YmdHis}_{name}.sql` in the migrations directory (default `./migrations` when no directory is passed to the constructor). The name must start with a letter and may contain letters, digits, dashes, and underscores. |
| `migrate` | Apply every migration that has not run yet, oldest first. |
| `migrate:rollback [--steps=N]` | Undo the most recently applied migration (or the last `N`). Fails if a migration has no `-- @down` section. |
| `migrate:status` | Table of all migrations and whether/when each was applied. |

A migration file holds the forward SQL, optionally followed by a `-- @down` line and the SQL that undoes it. Statements are split on a `;` at the end of a line. `migrate` and `migrate:rollback` print the error and exit `1` if a statement fails; most databases auto-commit DDL, so a migration that fails part-way is not rolled back.

### `claude:install`

Installs Claude Code agents, skills, and a starter `CLAUDE.md` into your project. This enables framework-aware AI assistance when using [Claude Code](https://claude.com/claude-code).

```bash
vendor/bin/melodic claude:install           # install (skips existing files)
vendor/bin/melodic claude:install --force   # overwrite existing agent and skill files
```

Installs:

| Type | Name | Description |
|---|---|---|
| Agent | `melodic-expert` | Framework expert for architecture, patterns, and debugging |
| Skill | `/melodic:scaffold-app` | Scaffold a new Melodic application |
| Skill | `/melodic:scaffold-resource` | Scaffold a full CQRS resource |
| Skill | `/melodic:add-middleware` | Scaffold a middleware class |

A starter `CLAUDE.md` is written to the project root only when none exists; `--force` never overwrites it. If a `CLAUDE.md` already exists and does not mention `MELODIC_PHP.md`, a short section pointing at the framework reference (`vendor/melodicdev/framework/MELODIC_PHP.md`) is appended to it.

See [Claude Code Integration](claude-code.md) for full details.
